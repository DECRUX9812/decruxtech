Evidence, not adjectives

We run what we sell.

Most IT firms will not show you their own setup, usually because there isn't much of one. Ours is the reference build: the same architecture we would put in front of a client, running the firm every day.

01

The firm runs on its own stack.

No reseller dashboard, no rented everything. The infrastructure that runs this practice is the one we would build for you, and it is boring in the way good infrastructure should be.

Reference build
Regina, SK

A private host, a mesh network, and a rule that nothing internal answers to an anonymous request.

Compute lives on a Proxmox host we control, not on a per-seat subscription. Every machine, phone and service joins a zero-trust mesh over WireGuard, which means internal tools are reachable from anywhere without exposing a single port to the open internet.

Anything that must be public goes through an edge that demands a verified identity first. Monitoring, metrics and traces run on the same box, so when something breaks we find out before a client does.

The point is not that this is exotic. The point is that we operate it daily, which is a different kind of qualification from having read about it.

02

The shapes the work takes.

Client work is confidential, so these are engagement patterns rather than named case studies. Each one is a real shape of problem we build for, with the outcome that matters.

Patterns
not logos
Pattern A

The clinic that cannot prove access

A practice with shared logins and a backup nobody has restored. Outcome: named accounts, MFA everywhere, one tested restore with a recorded time.

Pattern B

The trades firm losing quotes

Quotes photos and invoices spread across three phones. Outcome: one job record per customer, from first call to paid invoice.

Pattern C

The office running on one inbox

Intake, scheduling and reminders all living in one person's email. Outcome: a form that routes itself, with reminders that send on time.

Pattern D

The nonprofit rebuilding from a departure

A site and donor list built by a volunteer who has moved on. Outcome: documented ownership, exportable data, a site the staff can edit.
